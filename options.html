URL matching rules

A JSON array of { "name", "match", "key" } rules. A URL that matches a rule's match pattern is compared by its expanded key, so tabs whose URLs differ only in what the key leaves out are duplicates. The first matching rule wins; [] means URLs are compared as they are. Examples to start from and the pattern language are below.

Examples

"Add" appends a rule to the rules above; it takes effect once you click Save. Rules are tried in order, so put more specific rules first.

Patterns

A pattern is a hostname followed by path segments, separated by /. The scheme, query string and #fragment play no part in matching, and are left out of the key.

texta segment that must match exactly
{name}any one segment, captured as {name} for the key
{name:[0-9]+}one segment made only of the listed characters; ranges and ^ (not) work, other regular expression syntax does not
*any one segment, not captured
**whatever path is left, including none; only at the end
*.example.comany subdomain of example.com, not example.com itself
